# 后端结构重构记录

本次重构覆盖当前 `tg-bot` 后端仓库，不修改独立的前端仓库。

| 阶段 | 改动 |
| --- | --- |
| 1：业务一致性 | CLI 共用任务服务，账号共用登录和退出流程，发布版本与调度配置原子提交 |
| 2：运行时和数据层 | 提取任务、版本、进度、调度组件，按业务拆分 Repository，引入版本化迁移 |
| 3：接口和业务边界 | HTTP 路由、模型、响应、鉴权和生命周期拆分；账号与机器人按能力拆分 |
| 4：工作流和读取性能 | 提取步骤模型与处理器、复用 HTTP 连接、批量查询关联数据、共享日志增量读取 |
| 5：组装和收尾 | 接入应用上下文、提取运行协调和 Telegram 消息适配、拆分条件和安全组件、统一错误转换、更新文档 |

## 兼容策略

- 保留现有 HTTP 路径及响应字段，未要求前端同步改版。
- 保留任务 YAML 格式、旧条件格式、原始步骤回调签名和主要旧导入路径。
- 原有服务门面保留显式委托，后续新增逻辑放入实际职责组件。
- 保持同账号、同目标串行执行；正式运行与编辑器测试共用启动收尾，但测试不会更新正式任务状态。
- 没有将接口、运行时和数据库全面改为异步 SQLAlchemy，也没有引入微服务或新的外部依赖。

## 验证范围

按照 `AGENT.md`，本次没有新增或执行测试套件，没有进行本地页面视觉或交互验收，也没有连接真实 Telegram。

执行了源码编译、Ruff、mypy、差异空白检查以及入口导入检查；核对了重构前后全部 67 个 HTTP 方法与路径组合、现有测试源码引用的导出符号；在临时目录用独立 SQLite 数据库进行应用组装、OpenAPI 生成、重复初始化和 YAML 示例加载检查。临时检查显式禁用了真实通知与机器人，不使用项目 `.env` 或 `data/`。

这些检查不能替代运行时回归测试。合并前仍需按实际部署环境验证 PostgreSQL 历史数据升级、并发发布、取消与关闭，以及 Telegram 实际登录和消息交互。相关检查需要明确授权和对应环境。
